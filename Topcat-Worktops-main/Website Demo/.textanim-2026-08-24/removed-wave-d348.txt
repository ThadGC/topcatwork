THE WAVE — D348, removed the same night by D349.  PARKED, NOT DELETED.

WHAT IT WAS
    The words held still IN THE FRAME and a soft edge crossed the story layer left to right,
    erasing them piece by piece on the film's own measured pan.  One mask on `.cine-story`, static
    image, `mask-position` animated, 130px smoothstepped ramp.

WHY IT WENT
    It was the wrong reference frame, and the fault was mine.  He wanted the words STILL IN THE
    PICTURE, not still in the frame: *"the dot is just above the tip of the mountain. It never
    moves away from that position... all of the rest of the text will stay in its exact position
    and go off of the screen as the video turns past it."*  The words are pinned to the ground they
    stand on and ride it out of frame; the FRAME EDGE is the "wave that goes over it".  See D349.

WHY IT IS KEPT
    He has said the two beats will each get their own way of animating, one at a time, and a wave
    that erases in place is a real candidate for a beat whose shot does not move (the closing
    kitchen is locked off — measured zero camera motion).  Restoring is: paste the CSS block back
    inside the `@media(min-width:1121px)` block beside `.cine-hero`, paste the JS block above
    `const STORY=`, call `paintWave()` after `heroCopy()` in `tick()` and in the skip handler, and
    put back the `wide` branch in `story()` (git 65578d0 has all of it).

⛔ IT CARRIES ONE TRAP WORTH REMEMBERING: a `filter` on a masked element is what glitched the arrow
   at D339, so the beats' depth-of-field blur had to be turned OFF, not merely left unused.

  /* ⭐⭐⭐ THE WAVE — 23 August 2026 (D348). DESKTOP ONLY. His instruction, in full, is quoted over
     the CSS. The mechanism in one line: **the words never move and never fade; a single soft edge
     crosses the frame and takes them piece by piece**, and on the first screen that edge is the
     film's own pan.
     ⭐⭐ `PAN` IS MEASURED, NOT EASED BY TASTE. Per-frame global translation of the shipped 1920 cut
     (16x480 luminance strips, SAD over ±96 px), integrated and normalised over t=0…6: the picture
     runs left the whole time and ACCELERATES — 4 film px per frame at the start, 20 by the end, 572
     in total. These thirteen numbers are that curve at half-second steps, so the edge slows when
     the camera slows and drives when it drives. ⚠️ **Re-measure them if the film is ever re-cut**
     (`.src-2026-08-23/`, and the probe is in D348).
     ⚠️ **IT RUNS AT 1.6× THE PAN AND THAT IS DELIBERATE.** At 1:1 with the picture the last word
     would leave at **t≈7.4** (the block's right edge is 913 film px from the frame's, and the pan
     reaches that only then), which overruns the t=6 exit he has already approved. The PROFILE is
     the camera's; the rate is scaled so it lands where his timing says. */
  const PAN=[0,0.042,0.084,0.126,0.168,0.224,0.308,0.392,0.476,0.566,0.692,0.832,1];
  function panEase(f){
    const x=clamp(f)*12, i=Math.min(11,Math.floor(x));
    return PAN[i]+(PAN[i+1]-PAN[i])*(x-i);
  }
  /* ⛔ THE BAND IS THE STYLESHEET'S, READ IN `sync()` — the mask's own width and the position this
     file computes from it are one number, so they cannot be changed apart. The literal here is only
     what stands before the first read. See the CSS for why it is 130. */
  let WAVE_BAND=130;
  /* ⭐ THE BEATS HOLD, THEN THE WAVE CROSSES THEM. The first screen's edge is the camera's, because
     the camera moves; on the two beats the shot is all but locked — measured 136 px of drift on the
     slab and **zero** on the closing kitchen — so there is no pan to ride and the sweep is a
     designed gesture, given the same accelerating profile so the film still reads as one voice. */
  const BEAT_HOLD=0.55;
  const storyEl=hero.querySelector('.cine-story');
  /* the hero block's box and the proof block's box, in the story layer's own coordinates */
  const HW={x0:0,x1:0}, HT={x0:0,x1:0};
  let waveWant=-WAVE_BAND, waveHas=null, trustGone=null;
  const boxOf=(el,o)=>{ o.x0=el.offsetLeft; o.x1=el.offsetLeft+el.offsetWidth; };
  /* f=0 leaves the ramp's leading edge exactly on the block's left edge, so the block is whole;
     f=1 puts the image's left edge past its right edge, so the block is gone. */
  const waveAt=(x0,x1,f)=>x0-WAVE_BAND+f*((x1-x0)+WAVE_BAND);
  /* ⚠️ ONE WRITE PER TICK AT MOST, and rounded: a custom property re-set at full precision every
     frame is a style recalculation for nothing — the lesson `veil()`, `grade()` and `story()` all
     carry already. ⛔ Written by `tick()` AFTER both `story()` and `heroCopy()` have had their say,
     because they share the one edge. */
  function setWave(v){
    const w=Math.round(v);
    if(w!==waveHas){ waveHas=w; storyEl.style.setProperty('--wave',w); }
  }
  /* ⛔ HAND IT BACK ON THE WAY OUT OF THE BAND — an inline custom property survives a dragged
     window, and at ≤1120 there is no mask rule left to answer it. */
  function clearWave(){ if(waveHas!==null){ waveHas=null; storyEl.style.removeProperty('--wave'); } }
  /* ⛔⛔ **ONE OWNER, AND IT IS THE ONE THAT KNOWS THE BAND.** The first build cleared the property
     inside `heroCopy()`'s band-out branch and then wrote it again from the frame two lines later,
     so a phone carried a `--wave` for a mask that only exists at ≥1121. Caught by reading the
     element at 390px, not by looking at the screen — nothing was visibly wrong. */
  function paintWave(){ if(heroOn)setWave(waveWant); else clearWave(); }
