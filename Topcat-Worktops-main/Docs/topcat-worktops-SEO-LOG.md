## 1. Two things you must know before you touch anything

**1. Fabrication is OUTSOURCED, and the site must never say otherwise.**
TopCat advise, source the slab, laser-template, place the cut with long-standing fabrication
workshops, fit, and carry the ten year guarantee. Templating, fitting and aftercare are genuinely
theirs and can be claimed freely. Cutting and polishing are not. This was reversed on 7 Aug 2026,
having previously been presented as in-house, and every page on the site was rewritten. Do not
reintroduce "our own workshop", "we cut", "in-house fabrication" or equivalents. There is a scan
for this in section 8.

**2. Kitchens lead, but the business is not kitchens only.**
Kitchens are the biggest market and get the most focus: they lead the titles, the H1s and the
pricing tables. But TopCat also do bathrooms and vanity tops, splashbacks and upstands, utility
rooms, outdoor kitchens, commercial fit-outs, fireplaces, hearths and tables. Every material page
and every location page carries a "Not only kitchens" block linking to the service pages. Do not
strip it.

## 3. Internal linking structure

The spine is hub and spoke, with two-axis cross-linking so nothing is an orphan.
**Verified 9 Aug 2026: 3,393 internal links checked, 0 broken, 0 orphaned pages**, re-run after
the footer was cut (see the ⭐ note below). It was 4,185 on 7 Aug; the drop is the ~790 duplicate
sitewide footer links that came out, not lost coverage — the page count is unchanged at 89 and
orphans are still zero.

```
                          /  (landing page)
                           |
   footer links to all six families, on every page of the site
                           |
   +----------+------------+-------------+--------------+
   |          |            |             |              |
/materials/  /guides/   /worktops/   /services/      /trade/      /stones/
   |          |            |             |
   |          |            +-- county hub --> town page
   |          |                   ^              |
   |          |                   +--------------+ (town links back up to its county)
   |          |
   +----------+  materials <-> guides cross-link in both directions
   |
   +--> every material page links to 3 sibling materials and 2-5 relevant guides
   +--> every guide links to 2-4 sibling guides and the materials it discusses
   +--> every location page links to all 5 materials, 3 guides, its county, and 3 sibling towns
   +--> every material and location page links into /services/ via "Not only kitchens"
```

### ⭐ 9 Aug 2026 — the footer was cut, and what that means for crawl

The client asked for the footer to be cut back to main pages ("it's way too big… you won't have to
list everything out"). It went from **five link columns and 31 links to two columns and 17**, in
`index.html` and in all four page builders.

**What changed for SEO, precisely:** the Materials, Guides and Areas families are no longer listed
link-by-link in the footer of every page. Each family is now linked **once, at its hub**
(`/materials/`, `/guides/`, `/worktops/`), in a column headed **Browse**, and the hub links its own
children.

**Why this is safe, and arguably better:**
- Every page is still reachable in two clicks from any page on the site, and **orphans are still
  zero** (verified across all 89 non-V2 pages).
- Hub-and-spoke concentrates internal PageRank on the three hubs instead of spreading it flat
  across 25 sitewide links, which is the shape the rest of this document already recommends.
- It removes ~790 duplicated sitewide links. A large boilerplate link block repeated on every page
  carries little weight and is one of the patterns that makes a location-page set *look* like a
  doorway network.

⛔ **DO NOT remove the Browse column.** It is now the entire sitewide route into three page
families, and an unlinked page set is the textbook doorway signature — enforcement for which is
**site-level**. If the footer has to shrink again, take rows out of Explore instead.

⚠️ **"Services" points at `/index.html#services`, not a page.** There is still no `/services/`
index. The landing section lists all six service pages and links to each, so the family is not
orphaned, but this is the one family without a real hub and it should be built.

**Specific high-intent links into the landing page:**
- The footer's **Browse** column is the only sitewide route into Materials, Guides and Areas. See
  the note above before touching it.
- The footer's legal bar links `/sitemap.html` on **all 87 non-V2 pages**, which is a second,
  independent route to every URL. It is a belt-and-braces backup for the point above, not a
  replacement for it: a crawler that only reaches the sitemap gets a flat list with no topical
  grouping, which is exactly the shape that reads as a doorway set.
- `.est-readmore` sits directly under the estimator's help band, linking to all five material
  pages and the cost guide. This is the highest-intent internal link on the site, because it
  catches a visitor who is actively comparing materials.

**Hub page:** `/guides/best-kitchen-worktop-material.html` is the intended internal-linking hub.
It links out to all five material pages and every comparison guide. Point new comparison content
at it.

## 5. Location page strategy, and the rules that keep it safe

### The policy position
Google renamed "doorway pages" to **"doorway abuse"** (Sept 2024). The current definition turns on
**funnelling**: pages built to push users somewhere else. A town page that is itself the
destination is not a doorway. **"Scaled content abuse" is a separate, co-existing policy** and it
applies whether a human or a script wrote the pages. **Enforcement is site-level**, so a bad
rollout drags the whole domain, it does not fail quietly.

### The six rules this build follows
1. **Every page converts standalone.** Prices, process, applications, projects, phone, quote
   route. Never a stub whose only action is a click to contact.
2. **Nine real local variables per page**, not one find-and-replace: town + county in the H1,
   postcode range, local dialling code, named nearby areas, an honest travel statement, lead time
   in days, genuinely local housing-stock copy, two-axis internal links, and an FAQ with the town
   inside the question phrased so it reads naturally.
3. **County hubs are real pages**, so `/worktops/{county}/{town}/` is a browseable hierarchy,
   which is the policy's own stated escape from doorway treatment.
4. **Location pages stay under ~40% of indexable URLs.** Currently **26%** (9 of 34).
5. **Launch 8, gate at 90 days** before adding more.
6. **No LocalBusiness schema.** See section 4.

### URL choice
`/worktops/{county}/{town}/`. Renamed from `/kitchen-worktops/` on 7 Aug because the business is
not kitchens only. Google does not care about the pattern (ten different patterns rank), so this
was chosen for hierarchy signalling and honesty. The kitchen term is still carried in the title,
the H1 and an H2, which is where it matters.

### Towns chosen, and why these
Selected on **UK autocomplete demand, not affluence**. Harpenden, Windsor, Ascot, Chigwell and
prime-central London returned **zero** autocomplete variants despite being wealthy: too few
households, and residents search the nearest large town. Build where people search, qualify on
the page.

| Launched | Why |
|---|---|
| **Harlow** | 9 autocomplete variants, the standout of the whole dataset, weak dedicated-page competition, and TopCat has a real Harlow project |
| **Stevenage** | 8 variants, only ~11 Checkatrade competitors, best demand-to-competition ratio in Hertfordshire |
| **Enfield** | 7 variants, best London opportunity, stronger than Chelsea, Hampstead and Kensington combined |
| **St Albans** | 6 variants, best demand-plus-affluence pairing, included to prove we compete in a hard market |
| 4 county hubs | Hertfordshire, Essex, London, Berkshire |

### ⚠️ Phase 2 and 3, DO NOT BUILD UNTIL THE GATE PASSES
**Gate at 90 days: all 8 indexed, at least 6 with impressions, at least 3 with clicks.** Indexed
but flat on impressions means the content is wrong, and adding more makes it worse.

- **Phase 2 (+6):** Watford, Hemel Hempstead, Chelmsford, Romford, Slough, Wimbledon.
- **Phase 3 (+6-8):** Brentwood, Southend-on-Sea, Basildon, Maidenhead, Newbury, Berkhamsted,
  Richmond upon Thames, and one combined Loughton/Buckhurst Hill/Chigwell page.
- **Ship in batches of 6-8, spaced 6-8 weeks.** A single large publication event is itself a
  scaled-content signal.
- **Prune at every gate.** 90 days indexed with zero impressions, merge into the county hub
  and 301.
- **Cap the programme at 30-35 pages.** Rock and Co runs 21 and ranks #1.

### Berkshire caveat
Berkshire is county-page territory, not town-page territory, and it is the weakest of the four
counties. If drive time becomes a constraint, deprioritise it behind Hertfordshire and Essex.

## 6. Google Business Profile

- One profile, service-area business, **maximum 20 service areas**. The overall service area
  should not extend beyond about 2 hours' driving time.
- ⚠️ **Service-area settings have NO ranking effect, only visual** (Sterling Sky, daily rank
  tracking, updated 31 Mar 2025). Local pack ranking is driven by the verified address, reviews
  and prominence.
- **Therefore:** the local pack is won near the base and fades with distance, and location pages
  cannot change that. Location pages compete for the **organic links beneath the pack**, and they
  win there. For "granite worktops st albans", all seven organic results were location pages, not
  homepages.
- Point the GBP website field at the **homepage**, not a location page.
- **Ask for reviews that name the town and the fitter.** That copy serves GBP and the location
  pages at once, and it was the single strongest trust signal found across the competitor set.

## 7. The silica page: accuracy rules, do not edit casually

`/guides/is-quartz-safe-silica.html` is the biggest first-mover opportunity on the site. Across
four competitor sitemaps totalling 684 URLs there is exactly **one** safety page, and it mentions
silica zero times. It is also **YMYL**, so Google applies elevated scrutiny and errors are
expensive.

- ⚠️ **Never write "HSE banned dry cutting" as law.** HSE's own wording is that the guidance
  "effectively rules out dry-cutting" but "is not a new law, or a formal prohibition". The page
  says so carefully. Keep it that way.
- ⚠️ **There is no UK ban and none coming.** Australia banned engineered stone from 1 July 2024.
  The UK government explicitly **declined** a ban on 2 June 2026.
- ⚠️ **Never claim any product is "silica free" without a manufacturer SDS on file.** The most
  credible products qualify their own claim to "less than 1%" in the small print. Repeating a
  supplier's marketing claim on a health page is the real liability.
- ⚠️ **Porcelain is NOT the safe alternative.** Published data puts crystalline silica in
  porcelain slabs at roughly 15 to 25%, higher than several low-silica quartzes. The page says
  this plainly and the porcelain material page repeats it.
- The page's genuine differentiator is that, **because fabrication is outsourced**, TopCat can
  honestly describe what they require of and verify in their fabrication partners. No competitor
  is doing this.
- Keep the named author and the visible "last reviewed" date current. Bump `LAST_REVIEWED` in
  `build_seo_pages.py` when the copy is genuinely re-checked, not on every rebuild.

## 8. Compliance scans to run before go-live

⚠️ **The V2 filter was `grep -v "^./v2/"` until 7 Aug 2026 and it did not work.** BSD grep on
macOS prints `v2/faq.html`, not `./v2/faq.html`, so the anchored pattern matched nothing and
every scan came back full of dormant V2 hits. Anyone running the checklist would have learned to
ignore the output, which is the worst possible outcome for a checklist. It is `(^|/)v2/` now,
which is correct on both BSD and GNU grep.

```bash
cd "Website Demo"

# 1. Fabrication claims. MUST return nothing.
grep -ril "our own workshop\|we cut\|in-house fabrication\|cut, polish and fit" \
  --include="*.html" . | grep -Ev "(^|/)v2/"

# 2. Dead or forbidden schema. MUST return nothing outside v2 and code comments.
#    Expect ONE hit: the code comment in index.html recording that FAQPage was removed.
grep -rl "FAQPage\|aggregateRating\|reviewCount\|HowTo\|SearchAction" \
  --include="*.html" . | grep -Ev "(^|/)v2/"

# 3. Suppliers must never be RENDERED publicly.
#    Expect ONE hit: index.html, where `sup:` lives in the MATERIALS data and is never printed
#    (rule D8). Grep the rendered text, not the source, to check this properly.
grep -ril "nile stone\|next stone slabs" --include="*.html" . | grep -Ev "(^|/)v2/"

# 4. Never signal a young company.
grep -ril "est\. 20\|founded in 20\|since 20" --include="*.html" . | grep -Ev "(^|/)v2/"

# 5. JS syntax gate + JSON-LD validity (catches a missing comma before the browser does)
python3 - <<'EOF' > /tmp/x.js
import io,re
s=io.open('index.html',encoding='utf-8').read()
print('\n;\n'.join(p for p in re.findall(r'<script(?![^>]*application/ld\+json)[^>]*>(.*?)</script>',s,re.S) if p.strip()))
EOF
node --check /tmp/x.js

# 6. Broken links and orphans across the whole site.
#    ⚠️ Ignore hits containing "${" — those are JS template literals inside the inline
#    scripts in index.html, not real hrefs. There were 8 of them on 7 Aug 2026.
python3 - <<'EOF'
import re, pathlib
root = pathlib.Path('.')
pages = [p for p in root.rglob('*.html')
         if 'v2' not in p.parts and p.name not in ('index-v2.html', 'versions.html')]
def resolve(href, frm):
    href = href.split('#')[0].split('?')[0]
    if not href or href.startswith(('http', 'mailto:', 'tel:', 'data:', 'javascript:')):
        return None
    p = (root / href.lstrip('/')) if href.startswith('/') else (frm.parent / href)
    try: p = pathlib.Path(*p.parts).resolve().relative_to(root.resolve())
    except Exception: return None
    return p / 'index.html' if (root / p).is_dir() else p
broken, n, linked = [], 0, set()
for p in pages:
    t = p.read_text(encoding='utf-8', errors='ignore')
    for h in re.findall(r'(?:href|src)="([^"]+)"', t):
        r = resolve(h, p)
        if r is None: continue
        n += 1
        if r.suffix == '.html': linked.add(str(r))
        if not (root / r).exists(): broken.append((str(p), h))
print(f"{len(pages)} pages, {n} internal links, {len(broken)} broken")
for b in broken: print("  BROKEN", b)
print("orphans:", [str(p) for p in pages if str(p) not in linked and str(p) != 'index.html'] or "none")
EOF

# 7. The sitemap must reach every page. Rebuild it rather than editing it.
python3 build_seo_pages.py && grep -c 'href="/' sitemap.html
```
