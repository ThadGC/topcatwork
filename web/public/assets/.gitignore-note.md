# public/assets — what is here, and what is deliberately missing

This directory is a straight copy of the legacy site's `assets/` tree. The
paths are absolute and **must not change**: `/assets/fonts/…`,
`/assets/brand/…`, `/assets/site/…` are hard-coded in `globals.css`, in the
`<link rel="preload">` tags in `app/layout.tsx`, and in ~2,900 `src`/`srcset`
attributes across the 178 legacy HTML pages that later agents port from.

## Copied

| Path | Size | Used by |
|---|---|---|
| `fonts/` | 68 KB | the two `@font-face` blocks in `globals.css`; preloaded on every page |
| `brand/` | 52 KB | logo (`topcat-horizontal.svg`, `topcat-vertical.svg`), `favicon.svg`, `topcat-icon.svg` |
| `site/` | 6.0 MB | hero stills, page heads, process/service/team photography, `plate-stone-700.webp`, `og-cover.jpg`, `manifest.json` |
| `projects/` | 6.7 MB | the `/projects/` case-study galleries |
| `team/` | 400 KB | `/about/` portraits |
| `stone-floor.webp` | 92 KB | `--marbleBG`, i.e. `body::before` on every single page |
| `kitchen-day.jpg` | 392 KB | 13 references across the legacy pages |

Font files are byte-identical to source: `cinzel-latin-var.woff2` 25,904 B,
`montserrat-latin-var.woff2` 37,956 B.

`assets/slabs/` **is now copied** — 265 files, 39 MB. The 134 `/stones/*` pages
landed and they are its consumer, so it was wired following the same rule as
everything above: copied straight across, nothing renamed. All 264 distinct
`/assets/slabs/…` URLs in `src/data/stones.json` resolve to a file on disk; the
265th is a `.gitkeep`-style spare in the source tree. The home-page stone wheel
is the other consumer and needs no further copying.

## `assets/video/` — copied, and PARTLY RE-ENCODED

| Path | Size | Consumer |
|---|---|---|
| `video/` | **50 MB** | the home-page cine film (`#hero`, `html.cine-on`) |

This is the one directory where "copy it straight across, do not re-encode"
does **not** apply, and the reason is the scrub itself. The film is never
played; every frame is addressed as a still. The cost of that is set by the
GOP, because presenting frame N means decoding forward from the keyframe at or
before it. The two mobile cuts shipped at GOP 12 and juddered on phones.

| File | Was | Now |
|---|---|---|
| `topcat-intro-1920.mp4` | 1920x1080, GOP 8, 25.7 MB | unchanged — already on the recipe |
| `topcat-intro-864.mp4` | 864x1080, GOP 12, 6.8 MB | 576x720, GOP 4, 11.4 MB |
| `topcat-intro-608.mp4` | 608x1080, GOP 12, 6.3 MB | 406x720, GOP 4, 11.8 MB |
| `*-poster.webp`, `plates/**` | frame 0 of the old encodes | re-extracted from the new ones |

Two things survive that re-encode untouched and must keep surviving it:

1. **The frame timing.** `FPS=60`, `DUR=44.25`, and the per-band story-beat
   windows in `lib/timeline.ts` are all measured against the master, not the
   encode. Duration is preserved to the millisecond.
2. **The aspect ratio.** `lib/geometry.ts` maps the clip-path reveal tables
   through a cover fit computed from the aspect alone, then divides by the
   NOMINAL band width in `FILM_W` (1920 / 864 / 608 — not the encode width).
   864:1080 and 576:720 are both exactly 0.8, so the reveal still lands on the
   same edge in the footage. A squeezed encode would move it.

`scripts/encode-film.sh` is the recipe, and it extracts every poster from the
**encoded** clip rather than from the master — the poster is held on screen
until the decoder paints, and swapping it for a different image is a visible
pop.

Bump the `?v=` stamps in `src/components/HeroFilm/lib/constants.ts` whenever
any of this is re-cut. A visitor holding an old cut at an old stamp scrubs a
12-GOP film through an engine tuned for a 4-GOP one.

`next.config.ts` sets `images: { unoptimized: true }`, so all of it is copied
to `out/` untouched.
